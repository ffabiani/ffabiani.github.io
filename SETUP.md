# Publish the updated website

These files are prepared for the existing repository:
https://github.com/ffabiani/ffabiani.github.io

## 1. Upload the files

1. Unzip the downloaded archive on your computer.
2. Open the folder named `ffabiani.github.io-main`.
3. On GitHub, open your repository and choose **Add file → Upload files**.
4. Drag all the files and folders **inside** `ffabiani.github.io-main` into the
   upload area. Do not upload the ZIP or the enclosing folder itself. Dragging
   the folders preserves their structure.
5. Check that `_config.yml`, `Gemfile`, and `index.html` will be at the top level
   of the repository, beside `_data`, `_pages`, and `assets`.
6. Choose **Commit changes** and commit to `main`.

The upload replaces the existing `index.html` and `README.md` and adds the theme
configuration and additional pages. It does not require renaming the repository
or creating a new one. If you have edited files since downloading the original
ZIP, merge those changes before replacing them.

## 2. Enable GitHub Pages

Open https://github.com/ffabiani/ffabiani.github.io/settings/pages and set:

| Setting | Value |
| --- | --- |
| Source | Deploy from a branch |
| Branch | main |
| Folder | / (root) |

Click **Save**. GitHub will build the Jekyll site and fetch the Minimal Mistakes
theme automatically. The normal GitHub Pages build is sufficient; no custom
GitHub Actions workflow is required.

Open the **Actions** tab and wait for the Pages build and deployment to finish.
Then visit https://ffabiani.github.io. Publication can take up to 10 minutes.

## 3. Add your own content

In GitHub, open a file, click the pencil icon, edit it, and commit your changes.

### Profile and photograph

In `_config.yml`, change `author.bio` to your position and affiliation, and fill
in `author.location` if desired. Update the commented email and profile-link
examples with your real links before enabling them.

Upload a photograph as `assets/images/profile.jpg`, then change:

```yaml
  avatar: "/assets/images/profile.jpg"
```

Keep the two-space indentation under `author:`. YAML uses spaces, not tabs.
The FF initials remain visible until you add your photograph.

### Biography

Edit the paragraphs in `index.html`. Keep the settings between the two `---`
lines at the top. The page title and your name are generated by the theme;
you do not need to add another `<h1>`.

### Research, publications, and teaching

Edit the corresponding Markdown files in `_pages`. They include commented
examples for structuring your own content. The examples are not visible on
the published site. No sample papers or appointments are presented as yours.

### CV

1. Upload your PDF as `assets/files/CV.pdf`.
2. Change `cv_file` in `_config.yml` from an empty string to:

   ```yaml
   cv_file: "/assets/files/CV.pdf"
   ```

This enables the download link on both the homepage and CV page. Until then,
the CV page displays a short availability message without a broken PDF link.

### Menu and colors

Edit `_data/navigation.yml` to rename or remove menu entries. The included
Home, Research, Publications, Teaching, and CV links all have matching pages.
Removing a menu entry does not delete its page.

To change the theme palette, update `minimal_mistakes_skin` in `_config.yml`.
The current value, `default`, uses the standard Minimal Mistakes appearance.

## If the site does not update

- Check the latest Pages run in **Actions** for an error message.
- Confirm `_config.yml` is at the repository root, not inside a nested upload folder.
- Confirm **Settings → Pages** publishes `main` and `/ (root)`.
- This setup needs Jekyll. If a `.nojekyll` file was added later, remove it.
- If you later add `index.md`, first remove or rename `index.html` so both files
  do not generate the same homepage.
- After a successful deployment, refresh your browser without its cache.

## Validation

The package was checked for valid YAML, page metadata, unique output paths,
navigation destinations, local asset references, and archive integrity.
A full Jekyll build could not be run in the preparation environment because
Ruby and Bundler were unavailable. The first Pages deployment is the final
build check. The setup follows the theme's documented GitHub Pages method.
