# Add the grouped Publications page

Copy the four website files into the same paths in your GitHub repository:

- `_data/publications.csv` — your original Google Scholar export, unchanged.
- `_data/publication_rules.yml` — venue rules and documented exceptions.
- `_pages/publications.md` — replaces the current Publications page.
- `assets/css/publications.css` — styles for this page only.

Upload the contents into the repository root, preserving these folders; do not put the whole `publications-update` folder inside the repository. Commit the changes and wait for GitHub Pages to finish building. Your existing Publications menu link already points to `/publications/`.

The page has no author sidebar, uses the available content width, and inherits your light/dark theme. No change to `_config.yml`, `main.scss`, or `dark.scss` is needed. No additional plugin or GitHub Actions workflow is required.

## Current classification

- Preprints: 4 entries, including one explicitly labelled extended arXiv version of a published journal paper.
- Journal papers: 31 entries.
- Conference papers: 28 entries, including one explicitly labelled conference abstract.
- Other works: your 2019 PhD thesis.

All 64 CSV records appear once. Each section is grouped by year, newest first; within each year, titles are alphabetical. The totals count records, not necessarily distinct underlying research contributions. The extended arXiv version and its journal paper remain separate because the supplied CSV contains both.

## Updating your publications

Replace `_data/publications.csv` with a fresh Scholar CSV export using the same column headings. Commit it and GitHub Pages rebuilds the list. Existing known journals, conference markers and arXiv labels are classified automatically.

If a journal is new to the list, add its venue name in lowercase under `journal_venues` in `_data/publication_rules.yml`. Unrecognised venues appear under Other works so new records are visible rather than silently omitted. A missing year is shown as Year not specified. Review Other works after importing a new export.

For an exception, add an entry under `overrides`, using the exact CSV Title as the key. Supported display fields are `category`, `venue`, `year`, `url`, and `note`. Categories are `preprint`, `journal`, `conference`, and `other`. Quote the year. The optional `source` and `source_note` fields document the reason and are not displayed on the public page.

Example:

```yaml
  Exact title as it appears in the CSV:
    category: journal
    venue: Journal name
    year: "2027"
    url: https://doi.org/REPLACE_WITH_THE_REAL_DOI
```

If a title changes in a later export, update its override key too. When a preprint is published, update its Scholar record or add an override with the published venue/year. The website does not query Scholar or publishers to discover status changes. If the export contains both versions, it preserves both until you remove or merge them in the source export.
